# Установка и обновление

[English](Installation.md) · [Главная](Home-ru.md)

## Standalone на macOS

Возьмите архив из согласованного канала поставки. Сверьте архитектуру через `uname -m`, контрольную сумму через `shasum -a 256 <архив.zip>`. Для сборки x86‑64 на Apple Silicon нужна Rosetta. Оставьте бинарник и папку `_internal` вместе. Для распакованной сборки отдельный Python, Node.js и установка с правами администратора не нужны.

Распакуйте архив в новый каталог, например через `/usr/bin/ditto -x -k archive.zip ./gateway-release`. Затем запустите демо:

```sh
cd ./gateway-release/ag-mcp-gateway
./ag-mcp-gateway --version
./ag-mcp-gateway demo-profile
./ag-mcp-gateway serve --allow-unauthenticated
```

Демо создаёт синтетический локальный MCP. Обзор доступен на [127.0.0.1:18792](http://127.0.0.1:18792/). Во втором терминале выполните `./ag-mcp-gateway status`. Профиль создаётся один раз. Если файл уже существует, команда его не перезапишет.

## Рабочий профиль и обновление

По умолчанию профили лежат в `~/.ag-mcp-gateway/profiles`. Скопируйте один из примеров `profiles/*.example.json` в файл рабочего профиля. Имя в поле `name` должно совпадать с именем файла без `.json`. Укажите согласованные MCP, ссылки на секреты и правила инструментов. Опции `--profile`, `--profiles`, `--state` и `--port` передаются перед подкомандой.

Запустите `./ag-mcp-gateway --profile company-test serve`. Порты по умолчанию — 18792 без явной среды, 18793 для test и 18794 для production. Одновременно запущенным профилям нужны разные порты и каталоги состояния. Production требует токен. Для входа в браузере используйте пользователя `gateway` и токен профиля в качестве пароля.

При обновлении остановите старый процесс через Ctrl+C, сохраните профили и состояние, распакуйте сборку в новый каталог и запустите с прежним профилем. Если путь к бинарнику изменился, заново сгенерируйте настройки клиентов. Для отката сохраните старую сборку и разрешённую резервную копию состояния. Перед откатом проверьте совместимость состояния.

## Сборка архива macOS

```sh
python3 -m venv .venv
. .venv/bin/activate
python -m pip install -e '.[build,test]'
python -m pytest -q
python tools/build_standalone.py --output dist
```

Используйте Python целевой архитектуры. Архив включает бинарник, среду выполнения, README, вики, примеры и сведения о сборке. Для проверки из исходников используйте `python -m gateway --help`. Поддержку платформы подтверждайте испытанием на ней.

Для отдельной GitHub Wiki выполните `python tools/export_wiki.py /path/to/new-wiki-export` из каталога проекта. Команда подготовит публичные страницы со ссылками для Wiki. Перед импортом в инициализированную Wiki проверьте состав.
